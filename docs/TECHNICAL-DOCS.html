2. System Architecture

The system follows the standard Laravel MVC (Model-View-Controller) architecture with middleware-based role access control running on PostgreSQL.

  • Browser Layer: Blade templates with Tailwind CSS and Alpine.js
  • Route Layer: web.php — 150+ routes with role-based middleware
  • Middleware Layer: auth, security.headers, throttle:100,1, role:xyz
  • Controller Layer: 14 controllers handling business logic
  • Model Layer: 16 Eloquent models with PostgreSQL
  • Database Layer: PostgreSQL with 20 tables

5. Authentication Flow

1. User submits email + password
2. Brute-force check: LoginAttempt model (5 attempts/15 min lockout)
3. CAPTCHA trigger after 3 failed attempts (math challenge)
4. Auth::attempt() with bcrypt verification (12 rounds)
5. If MFA enabled → redirect to /mfa-verify → TOTP check
6. Session regeneration + last_login_at update
7. AuditLog entry created (login event with IP/UA)
8. Redirect to dashboard with role-specific data

9. Key Design Patterns

  • MVC Architecture: Models → Controllers → Blade Views
  • Role-Based Access Control: RoleMiddleware checks role->name against allowed list
  • Repository Pattern (via Eloquent): Models with scopes for reusable query logic
  • Service Layer (POS): Session-based cart management in PosController
  • Observer Pattern: Eloquent events for audit logging
  • Strategy Pattern: Multiple payment methods in POS checkout
  • Soft Deletes: Products use Laravel's SoftDeletes trait
